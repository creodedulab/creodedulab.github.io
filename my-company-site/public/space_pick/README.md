# SPACEPICK

`index.html`을 Chrome 또는 Edge에서 열면 실행됩니다. 설치나 인터넷 연결은 필요하지 않습니다. `index.html`, `style.css`, `spacepick.js`, `vendor`, `audio` 폴더를 함께 보관하세요.

공 종류 수, 이름별 공 개수, 뽑을 공 개수를 설정하고 오로라 서킷 우주 트랙에서 레이스를 시작하세요. 시작하면 설정 화면이 사라지고 3D 레이스로 전환됩니다. 구슬은 핀, 이동 범퍼, 회전 막대, 다른 구슬과 충돌하며 굽이진 트랙을 굴러갑니다. 카메라는 선두를 추적하며 시점, 배속, 일시정지를 바꿀 수 있습니다. 모든 공이 완주하면 먼저 도착한 순서로 당첨 공을 표시합니다. 같은 이름의 공도 각각 참여하므로 중복 당첨이 가능합니다.

Marble Pick의 참가 목록·장애물 추첨 흐름과 Marble Race 3D의 테마별 입체 트랙·추적 카메라를 참고해 새로 작성했습니다. 두 사이트의 코드나 그래픽을 복사하지 않았습니다.

화면은 Three.js r170으로 렌더링합니다. 시뮬레이션은 트랙 진행 거리와 좌우 위치에서 구슬의 이동·충돌을 계산하며, 자유로운 3차원 강체 물리 엔진은 아닙니다. 당첨 결과는 도착 순서로 결정됩니다. 공식 경품 추첨을 위한 공정성 검증은 포함하지 않습니다.

`node verify.cjs`로 설정 수량, 완주, 결과 개수, 도착 순서, 좌표 유효성을 확인합니다.

오로라 서킷은 출발 궤도 → 잔해 지대 → 회전 방어선 → 소행성 벨트 → 최종 우주 관문으로 구성됩니다. 뒤로 갈수록 트랙이 좁아지고 이동·회전 장애물이 빨라지며 여러 방해 요소가 결합됩니다. 배경에는 별, 성운, 행성과 떠다니는 암석이 있습니다.

소행성과 우주선 이벤트는 공이 해당 구간에 접근하면 1.8초 경고 후 발동합니다. 소행성은 트랙을 가로질러 공과 충돌하고, 우주선은 견인 빔 범위의 공을 감속시키며 옆으로 끌어당깁니다. 이벤트 위치·범위·시간은 3D 표시와 시뮬레이션이 같은 값을 사용합니다. 공이 오래 남아 있으면 재사용 대기 후 이벤트가 반복됩니다. 일시정지와 배속은 이벤트에도 적용됩니다.

개발 소스는 `obstacles.js`, `race.js`, `audio.js`, `launch.js`, `app.js`입니다. 수정 후 `node build.cjs`를 실행하면 배포용 `spacepick.js`가 만들어지고 HTML의 파일 버전이 갱신됩니다. 시뮬레이션과 화면 코드를 하나로 묶어 서로 다른 버전이 섞이지 않게 합니다.

기본 설정은 1~20번 공과 당첨 1개이며, 1~500번까지 자동으로 번호를 생성할 수 있습니다. 공 종류와 전체 공 개수는 각각 최대 500개입니다. 트랙 길이는 1050 단위입니다. 좌측 실시간 순위표는 전체 공을 표시하며 스크롤할 수 있습니다. 먼저 도착한 공 중 당첨 수에 해당하는 행은 도착 즉시 별표와 다른 배경색으로 강조됩니다. 최종 결과 바로 보기 버튼은 진행 중인 동일 레이스의 나머지 시뮬레이션을 빠르게 계산해 결과를 보여줍니다.

기본 카메라는 구슬 뒤에서 진행 방향을 바라보며 따라갑니다. 장애물 설계는 `obstacles.js`의 50종 카탈로그로 관리합니다. 매판 분기 수와 갈래 수에 따라 68~100개 장애물 구간을 무작위로 선택하며 동일 설계는 최대 두 번 사용합니다. 가속과 감속 장치는 각 레이스에 최소 한 종류씩 들어갑니다. 분기 구간은 매판 1~4곳, 각 구간의 길은 2~4갈래로 무작위 배정합니다. 실제 노면과 안쪽 난간이 갈라지며 각 공은 선택한 길을 따라가다 합류합니다.

가속은 보통 3초, 감속은 2.5초 동안 적용되며, 구슬 발광·이름표·실시간 순위표에 효과를 표시합니다. 장애물의 배치, 충돌, 회전·이동 위치, 속도 효과는 시뮬레이션과 화면이 같은 설계 데이터를 사용합니다. `obstacles.js` 수정 후에도 `node build.cjs`를 실행하세요.

기본 카메라는 구슬 뒤에서 진행 방향을 보는 추적 시점으로 복원했습니다. 분기의 각 갈래에는 4~6개 장애물 구간을 배치합니다. 이 장애물들도 전체 구간 수 및 동일 설계 최대 두 번 제한에 포함되며, 좁은 길의 폭에 맞춰 배치·크기를 조정합니다. 강한 장애물 접촉은 반발과 짧은 충돌 신호를 만들고, 화면에서는 섬광·확산 고리·입자와 작은 튀어 오름으로 표시합니다. 정지 접촉은 효과를 반복 발생시키지 않으며 일시정지는 효과도 함께 멈춥니다.

장애물 이름표와 가속·감속 장치의 떠 있는 이름표는 표시하지 않습니다. 분기·합류 이름표도 표시하지 않습니다. 레일 가까이에 붙은 장애물 10종을 포함해 전체 50종을 사용하며, 매판 측면 전용 구간을 최소 10개 배치합니다. 일반 장애물도 중앙·좌측·우측으로 번갈아 옮겨 트랙 가장자리를 따라가는 단순 회피 경로를 없앴습니다. 모든 종류의 중복은 여전히 최대 두 번입니다.

출발 시 모든 구슬은 공중의 유리 캡슐 안에 들어 있습니다. 3·2·1 카운트다운이 끝나면 양쪽 바닥 뚜껑이 열리고 구슬이 자유 낙하한 뒤, 각 구슬이 트랙에 도착한 시점부터 레이스 물리가 적용됩니다. 최대 500개 구슬도 캡슐 크기를 늘려 수용합니다.

음악은 SPACEPICK 전용으로 합성한 오리지널 스테레오 WAV 두 곡입니다. 설정 화면은 Silent Orbit(60 BPM, 우주 앰비언트), 레이스는 Escape Velocity(136 BPM, 긴장감 있는 전자음악)입니다. `node compose-music.cjs`로 재제작할 수 있습니다. 브라우저 자동 재생 정책 때문에 최초 클릭 후 음악이 시작되며, 켜기·끄기와 음량을 조절할 수 있습니다. 설정 음악은 출발할 때 멈추고 3·2·1 비프음 이후 레이스 음악으로 전환됩니다. 레이스 일시정지 및 화면 비활성화 시 음악도 멈춥니다.

실행 미리보기에서 내부 오류가 표시될 경우 `SPACEPICK-실행.cmd`를 더블클릭하세요. 전용 로컬 서버가 시작되고 기본 브라우저에서 http://127.0.0.1:8947/ 주소를 엽니다. 서버는 이 컴퓨터의 루프백 주소에서만 접속할 수 있습니다. 미리보기의 blob/about 주소에서도 오디오 경로 초기화가 전체 화면을 중단하지 않도록 처리했습니다.

음악 기본값은 켜짐(70%)이며 페이지 로드 시 설정 음악 자동 재생을 시도합니다. 브라우저가 유성 자동 재생을 차단하면 상태 버튼에 클릭 재생으로 표시하고, 첫 클릭에서 재생을 재시도합니다. 브라우저의 자동 재생 제한을 우회하지 않습니다.

출발 낙하는 시각 위치식 대신 시뮬레이션의 높이·수직 속도에 중력 가속도를 매 시간 적용합니다. 트랙 접촉 시 수직 속도를 반사하여 두 번 점점 낮게 튄 다음 바닥에서 구르며, 착지 충격의 일부가 전진 속도로 이어집니다. 최초 착지에는 짧은 눌림·복원 연출도 있습니다. 화면에 보이는 장애물 충돌은 강도와 좌우 위치에 맞춘 타격음을 재생합니다. 바닥 착지는 낮은 소리, 장애물 접촉은 짧고 높은 소리로 구분하며 음악 음소거·음량·일시정지에 따릅니다. 동시 발음 수와 최소 간격을 제한해 500개 공의 소리가 한꺼번에 과도하게 겹치지 않게 합니다.

음악 기본 설정은 켜짐·70%로 고정합니다. 버튼의 켜짐/꺼짐 표시는 실제 재생 준비·브라우저 차단 상태와 분리해 사용자의 설정만 나타냅니다. 사용자가 직접 음악 버튼이나 음량을 바꾼 경우에만 해당 설정을 브라우저 저장소에 저장하고 다음 방문에 복원합니다. 레이스 시작, 일시정지, 결과 표시, 자동 재생 실패는 음악 설정을 변경하지 않습니다.

`SPACEPICK-실행.cmd`는 자동 재생을 허용한 SPACEPICK 전용 Chrome/Edge 앱 창으로 실행합니다. 이 창은 프로젝트의 `.spacepick-browser` 전용 프로필을 사용하며 클릭 없이 설정 음악이 시작됩니다. 일반 탭이나 Codex 내장 브라우저는 해당 브라우저의 자동 재생 정책이 그대로 적용됩니다.

레이스 속도는 기본 24.7, 전진 가속도는 9입니다. 분기의 각 길에는 4~6개 장애물 구간을 배치하며, 종방향 내부 간격은 기존의 80%입니다. 측면 전용 구간은 최소 10개이며 50종 카탈로그와 동일 종류 최대 두 번 제한을 유지합니다.

최적화: 물리 계산은 구간별 장애물 후보와 한 번 계산한 움직임 값을 재사용합니다. 구슬은 인스턴싱 3개 묶음(본체·줄무늬·하이라이트)으로 그리며 고정 장애물은 재질과 구간별로 합칩니다. 순위표는 기존 행을 재사용하고, 보이는 이름표만 제한 주기로 갱신합니다. 물리 단계 사이의 렌더링 위치 보간으로 움직임을 부드럽게 합니다. 최대 렌더링 픽셀 비율은 1.5입니다. 검증 측정값은 `physics-performance-results.json`, `performance-results.json`에 있습니다. 구슬 수, 속도, 장애물 밀도, 충돌·낙하·음악 설정은 최적화 때문에 바꾸지 않습니다.

코스 조정: 길이 840 → 1050(+25%), 기본 속도는 최초 기준 19의 1.3배인 24.7입니다. 폭은 부드러운 곡선으로 연결된 구간별 프로파일을 사용해 넓은 구간과 병목 구간을 오가며, 충돌 경계와 3D 노면이 같은 폭 데이터를 사용합니다. 초반 75 단위까지는 출발 정리 구간이며 이후 여섯 개의 완만한 장애물 구간을 둡니다. 초반 충돌 반발을 줄이고, 선두가 190~280 구간을 지나는 동안 사라지는 약한 후방 추격 가속을 적용합니다. 위치를 이동시키거나 당첨자를 미리 정하지 않습니다. 초반 평균 격차 비교는 `intro-pack-results.json`에 있습니다. 동일 종류 최대 두 번 제한·음악 설정은 유지합니다.

최근 코스 조정: 공 위 이름표는 PC 18px, 모바일 15px이며 배경과 테두리를 강화했습니다. 분기는 매판 1~4곳, 각 분기는 2~4갈래입니다. 넓게 펼쳐지는 분기를 카메라가 모두 담도록 높이를 조정합니다. 결승선 전 150 구간에는 고정·회전·이동·측면·가속 장치를 포함해 장애물 여섯 곳을 배치합니다. 마지막 장애물은 결승선 25 단위 전에 있으며, 충돌형 장애물의 크기와 움직임도 이전보다 강화했습니다. 좁은 길에는 폐쇄형 군집 대신 열린 지그재그 모양으로 배치하며, 공이 오래 정체되면 여유 있는 쪽으로 회전력을 주어 벽과 장애물 사이에서 벗어나게 합니다. 음악 파일·기본값·사용자 저장 설정은 변경하지 않습니다.
